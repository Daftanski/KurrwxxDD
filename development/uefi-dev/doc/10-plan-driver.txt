Full driver verification plan (levels 0..9)
===========================================
Scope:   CNIC UEFI driver E4999X10.EFI (nic-core CnicPkg + NicCorePkg),
         on Simics (development/uefi-dev). Black box from the UEFI
         Shell + small test apps; white box via unit tests.
Updated: 2026-11-06
Related: 11-results-driver.txt (func tests status, leak 3.6)
         12-plan-network.txt
         02-test-guide.txt
         ../misc/readme.txt


1. How to read this plan
------------------------
Levels go from simple to complex. Do not start a level before the
level below it is green (or its fails are known and written down).

    ID      L<level>.<n>
    What    the behavior to check
    How     tool / steps
    Pass    exact pass rule
    State   HAVE  = test exists (name)
            NEW   = can be written now with the Shell + lib.sh
            TOOL  = needs a new UEFI app (section 12)
            SIM   = needs Simics control (fault injection, link)
            OS    = needs an OS boot after UEFI
            WRIT  = test written, not run yet (name)
    Class A/B/C (any driver / any NIC driver / CNIC only):
    13-plan-generic.txt 2.

Facts about the driver used below (approximate lines):
    - Image handle: DriverBinding, ComponentName2, DriverDiagnostics2,
      DriverHealth, DriverSupportedEfiVersion, Unload.
      (NicCorePkg/Dxe/DriverEntryPoint.c)
    - Children (8 = PcdMaxChildrenNumber): DevicePath (MAC node),
      NII 3.1 (UNDI), AdapterInfo, HIIConfigAccess, FMP (on 1 child
      in the tests). (NicCorePkg/Dxe/DriverBindingStart.c ~286-458)
    - Rings: RX/TX 512 x 2048 bytes. No jumbo. Ctlq 16 x 4096.
    - ExitBootServices event: HalExitBootServices, bus master off.
      (DriverEntryPoint.c ~60)
    - Diag LAN loopback PCDs are 0 in the Cnic build (11-results-driver.txt 9.1).

11. Memory leak follow-up (11-results-driver.txt 3.6)
----------------------------------------
Facts (2026-10-30, tracker in ../misc/tools/leaktrack/, log ../../../.logs/2026-10-30_
leaktrack_stage2.log):
    - All gBS allocations made by the driver itself are freed by
      Unload (0 live CnicDxe allocations after unload).
    - Per Start/Stop, other drivers keep ~100 small pool blocks
      (~7 KB): HiiDatabase 40 x 20 B, HttpBootDxe 16, Ip4Dxe 8,
      Ip6Dxe 16, VlanConfigDxe 8 x 304 B. These are made during
      "connect -r" by the network stack on our children.
    - Live peak ~20000 allocations during Start. BS_Data loss per
      cycle (136 pages) is >> live bytes (~6 pages): pool pages are
      pinned by the few kept blocks (fragmentation). Not visible
      to the gBS hook: DxeCore internal pool (handles, protocol
      entries, events).
Open:
    L11.1 Same tracker numbers with a 2nd NIC driver (e.g. e1000
          model, if Simics has one) -> if same residue, not ours.
    L11.2 openinfo / dh count of the controller per cycle (is a
          DxeCore entry kept?).                           State NEW
    L11.3 Symbols of the platform firmware to map HiiDatabase+199FC
          etc. to source lines.
